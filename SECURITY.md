## Повторная проверка 25 октября 2026

При отдельном custom scan Microsoft Defender с параметром DisableRemediation исходный архив ExifTool и фактически использованная распакованная папка получили результат found no threats (код 0). Все 1501 файл из архива в этой папке совпали с ним по SHA-256. Дополнительные файлы вне списка архива этой сверкой не проверялись. Это результаты конкретных проверок, а не гарантия безопасности.

EXE v1.2.0 с указанным выше хешем статически разобран из существующего ZIP без запуска. Хеш вложенного ресурса exiftool.zip совпал с исходным архивом; обнаружены только используемые системные ссылки .NET, P/Invoke-методов нет. Полное доказательство соответствия IL исходникам не выполнено.

Сравнены ранний локальный EXE (SHA-256 e440b072dc626022645eee320b2637e806ea3775232a9981e6bfae524ad16b8c, custom scan: found no threats) и EXE из ZIP v1.0.0 (SHA-256 061a5156e682009c072ab99cbc39c09b324ddb4f535ff76f0b2c44bc8c61e79d, Wacatac). Файлы отличаются ровно 18 байтами: временем компиляции COFF и идентификатором MVID. Код и ресурсы совпадают. Это поддерживает предположение об эвристическом срабатывании, но не заменяет решение антивирусного поставщика.

Найден отдельный дефект безопасности исходника: ExtractTool повторно использует предсказуемую временную папку по наличию .complete и ExifTool.exe без проверки содержимого. Это допускает использование подменённого кэша. Текущая сверка не обнаружила подмены файлов из архива; доказательств эксплуатации и связи с обнаружением нет. Дефект пока не исправлен.

Версия 1.2.0 не является безопасным обходным вариантом. В ней также есть воспроизводимая ошибка передачи UTF-8 команд ExifTool: в окружении с UTF-8 консолью первая фотография может остаться необработанной. Версия 1.2.1 исправляет передачу команд; измеренного сравнения скорости между версиями нет.
